# x7peeps 漏洞研究文章写作

本技能用于编写漏洞研究专题，适合 CVE 分析、组件漏洞复盘、原理拆解、利用链梳理、修复建议与蓝队视角总结。

## 何时调用

- 用户要求“写一篇漏洞分析文章”
- 用户给出 CVE 编号，希望整理成完整研究稿
- 用户要批量生成漏洞专题内容
- 用户需要把已完成的漏洞验证过程整理成正式文章

## 目标

- 文章结构完整，可用于博客发布、知识库沉淀或研究归档
- 重点解释漏洞成因、影响范围、利用前提、攻击链和防御建议
- 保持证据链清晰，不做无依据夸大

## 工作流

1. 先确认目标漏洞：产品、版本、漏洞类型、公开编号、时间线。
2. 收集基础材料：官方公告、补丁说明、提交记录、研究博客、POC、复现条件。
3. 先梳理“漏洞是什么”和“为什么会发生”，再写利用与检测。
4. 如果已有复现结果，提炼成读者可理解的利用流程。
5. 若用户要求高质量专题稿，补充时间线、影响评估、修复建议、蓝队检测点。
6. 若材料不足，明确哪些部分为公开已知、哪些部分待验证。

## 推荐结构

```markdown
# 漏洞标题

## 基本信息
## 漏洞成因
## 影响范围
## 利用条件与攻击面
## 利用链 / POC 思路
## 修复与缓解
## 检测与排查建议
## 参考资料
```

## 写作要求

- 优先写清边界：受影响版本、默认配置、触发条件
- POC 和利用描述以原理说明为主，避免无约束地输出危险细节
- 不把“理论可利用”直接写成“已大规模利用”
- 如果引用第三方研究，保留出处并区分公开事实与分析推断
- 对尚未亲自验证的利用链使用审慎措辞

## 配套输出

- 漏洞研究正文 Markdown
- 摘要与标签建议
- 时间线要点
- 修复建议与防守侧检查清单

## 特别注意

- 如果文章要面向安全从业者，优先补充攻防视角、资产识别方式和排查线索。
- 如果用户明确要求“专题批量产出”，先给选题列表和优先级，再逐篇展开。
- 如涉及可能导致误用的攻击细节，优先提供高层原理、补丁差异与检测思路。
